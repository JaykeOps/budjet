# A Crownkeep subfolder, written one write at a time

ADR 0004 promises that every change survives a sync merge, which fixes the Data Folder as many small records instead of one rewritten file. This decides how those records sit on disk and reach it. Crownkeep writes only inside a `Crownkeep` subfolder of the folder the user chooses, which is also how any device recognises a Budget, and keeps one file per device per Month (`<device id>-<YYYY-MM>.jsonl`, in UTC, from the record's own wall time), one JSON record per line. Each device appends only to its own files. Readers take every file in the subfolder whatever its name and ignore repeated record ids, so old files can be combined later without a migration, and a retried write that repeats a line does no harm; file names are never to be parsed.

Every device also keeps a Local Copy of the records in browser storage and opens from it, because reading a folder is too slow on a phone and access to it can lapse. The folder is what syncs and can rebuild the copy, so the copy's format may change. Writes run one at a time: a queue within a tab, and a Web Lock shared between tabs, held across the whole write. Without this, overlapping writes lose records with no error: `createWritable` replaces the file on close, and in two runs on Android 12 writes reported success and 4 lines survived. A change counts as saved only when its write has finished, and until then it stays marked in the Local Copy, so a reload or a new session keeps trying. Where the browser has no folder picker, the Budget stays in Browser storage on the plain IndexedDB adapter; detection only ever asks whether the picker exists, never which browser it is.

The folder is reached through a narrow interface, so tests can substitute an in-memory fake that loses overlapping writes the way the real one does. Changing the layout later means migrating every user's Data Folder.
